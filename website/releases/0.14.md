# vitest-native 0.14

0.14 runs Expo SDK 56–58 projects on real React Native with nothing extra installed, makes React
Native Testing Library work without jest-compat or globals, and makes the native engine answer more
as a device and Jest do. Per-file isolation stays the default; the hot runtime, which is faster on
most suites, is opt-in.

This page covers what changes for a project on 0.13. Every entry, with the detail behind it, is in
the [changelog](https://github.com/danfry1/vitest-native/blob/main/packages/vitest-native/CHANGELOG.md).

## Before you upgrade

- **Node 22.13 or later on Node 22, or Node 24.3 or later.** `engines.node` is
  `>=22.13.0 <23 || >=24.3.0` (it was `>=20.19.0`). Node 20 reached end of life in April 2026, and on
  Node 24.0–24.2 `jest.mock`, `jest.isolateModules` and `jest.resetModules` do not reach modules Node
  loads. `vitest-native doctor` checks the range.
- **Snapshots that contain an asset change.** `require('./logo.png')` now evaluates to the number
  React Native's asset registry assigned, as with Metro, instead of the file name. Re-record them
  with `vitest -u`.
- **Native modules answer as on a device.** Under the native engine, `NativeModules[name]` and
  `TurboModuleRegistry.get(name)` are `undefined`/`null` for a module no app registers, and a React
  Native module's stub has only the methods its codegen spec declares. Register a module a test
  needs with `mockNativeModule(name, impl)` from `vitest-native/helpers`;
  `nativeModules: 'permissive'` restores the earlier behaviour.
- **Expo modules run as their installed packages.** Under the native engine, the `expo` preset no
  longer replaces `expo-constants`, `expo-status-bar`, `expo-font`, `expo-asset`,
  `expo-splash-screen` and `expo-linking`. Their values are jest-expo's: `Constants.expoConfig` is
  `{}`, `Linking.createURL()` needs a scheme mocked into `expo-constants`, and `Font.isLoaded()` is
  `false` until a font loads. `presets: { expo: true }` keeps the preset while a suite moves off it.
- **Presets of your own are listed by path.** A preset object passed to `presets` is refused at
  startup. List the module that exports it instead:
  `presets: { './test/presets/my-lib.ts': true }`.
- **`hotRuntime: true` is stricter.** Combined with a configured pool, `test.isolate` or a
  conflicting CLI flag, it fails at startup with `HOT_RUNTIME_OVERRIDDEN` instead of warning and
  overriding.
- **Release candidates rc.1 to rc.8 defaulted to `hotRuntime: 'auto'`.** 0.14.0 does not (see
  below). A project that relied on it sets `hotRuntime: 'auto'` to keep it.

## The hot runtime is opt-in

`hotRuntime` defaults to `false`, as in 0.13: under the native engine each test file runs in a
fresh worker. The hot runtime reuses workers across files and is faster on most suites:

```ts
reactNative({ hotRuntime: 'auto' })
```

- When it is active, the startup banner says so: `(platform ios, hot runtime)`. With `'auto'`, it
  keeps per-file isolation whenever the run cannot be bounded, or when you set a pool or
  `test.isolate` yourself, and prints the reason.
- Its known differences from per-file isolation are listed in
  [Troubleshooting](/guide/troubleshooting#a-test-passes-on-its-own-but-fails-when-run-with-other-files).
- It no longer drops test files from a run. A file whose worker broke is reported as failed by
  name.
- Hot workers leave Node's compile cache off when they re-evaluate ES modules, so the cache no
  longer grows with every test file. That costs about 15–20 ms per worker boot;
  `hotRuntime: { esmGeneration: false }` keeps the cache on.
- The memory plan is sized for the workers that actually run, and a worker count you set is limited
  only by memory. The cap of four applies only when the count is automatic; set `maxWorkers: 4` to
  keep it.
- `vitest-native init` and `migrate` end with a note on how to turn it on.

## Expo

- **Expo SDK 56–58 projects run real React Native with nothing extra installed.** When
  `@react-native/babel-preset` does not resolve (from SDK 56, `babel-preset-expo` no longer depends
  on it), the native engine compiles with Expo's preset, as Metro does. `reactNative()` used the
  mock engine there before.
- **React Native 0.88 and Expo SDK 58 join the supported matrix**, with an SDK 57 consumer alongside
  the SDK 58 one.
- **Expo's native modules answer as under jest-expo.** They come from a package's own `mocks/`, or
  else from the table of Expo's native modules that jest-expo ships, carried for SDK 57 and 58. On
  an Expo SDK 58 app, every probe of the six packages listed above matches jest-expo.
- **Expo's globals are installed before your setup files, and `fetch` stays Node's.** A `fetch`
  mocked in a setup file, an MSW server, nock and undici's `MockAgent` keep working whether or not a
  test imports `expo`.
- **Path aliases resolve.** On Vite 8, imports through tsconfig `paths` (the template's `@/…`)
  resolve as Expo's Metro resolves them; a `vite-tsconfig-paths` plugin or a hand-written alias for
  them can go.
- **expo-image can be imported**, and a test that imports `expo` or `expo-router` from SDK 58 no
  longer hangs.
- **`migrate` translates jest-expo presets**; see the [Expo guide](/guide/expo#coming-from-jest-expo).

## React Native Testing Library without jest-compat

- `findBy*`, `waitFor` and `userEvent` advance `vi.useFakeTimers()`. If you called
  `vi.advanceTimersByTime` before a query as a workaround, you can drop it.
- A setup file that calls `vi.useFakeTimers()` no longer hangs RNTL.
- RNTL's automatic cleanup runs without `test.globals: true`. A suite that relied on trees staying
  mounted between tests imports `@testing-library/react-native/pure`.
- With RNTL 12 or 13 under the native engine, `getByText` finds a nested `<Text>` by its own text.

## Closer to Jest and to the device

- **A project file imported and required in one test is one module.** Under the native engine, with
  or without jest-compat, `vi.spyOn`, export assignments and `instanceof` reach both sides, as under
  Jest.
- **`jest.mock` reaches `require()`.** With jest-compat, a `jest.mock` factory applies to
  `require()`, to `jest.requireActual`'s dependencies and to React Native's own requires of a
  mocked internal. `jest.isolateModules` and `jest.isolateModulesAsync` work.
- **jest-compat follows Jest more closely.** A name a `jest.mock` factory leaves out is `undefined`
  instead of an error, `new` on a `jest.fn` with an arrow implementation works, and
  `process.env.JEST_WORKER_ID` is set.
- **Assets are registered ids**, so `Image.resolveAssetSource(require('./splash.png'))` resolves as
  on a device instead of returning `null`.

## New and changed presets

- **Unistyles and Skia are mocked automatically.** The new `unistyles` and `skia` presets are
  auto-detected. Remove Unistyles' `react-native-unistyles/mocks` setup file (`vitest-native
  migrate` removes it) and any hand-written Skia mock. Skia's preset loads CanvasKit before each
  test file, about 20–30 ms; `presets: { skia: false }` turns it off.
- **react-native-mmkv 3 and later run as themselves**, with their own in-memory backend. The `mmkv`
  preset now applies to mmkv 2 only.
- **The startup banner names the presets a run applies**, for example
  `mocked: navigation, safeAreaContext, screens`.

## Faster runs

- **Vitest 5 keeps transformed modules on disk.** The plugin turns on Vitest's `fsModuleCache`
  unless your config sets it, keyed so that upgrading vitest-native or any dependency invalidates
  it. Warm runs of a 104-file production Expo suite were about 11% faster. Set
  `test.fsModuleCache: false` to opt out.
- **A library a worker loads again in each test file is no longer re-resolved and re-read every
  time**, including on Node 26.
- **Under the hot runtime, externalized imports are no longer re-resolved for every test file.**

## Tooling and setup

- **Vite+ projects start.** The Vite and Vitest versions are read from the running instances, so
  Vite+ no longer fails with `UNSUPPORTED_PEER`. Two physical copies of Vitest stop the run at
  startup with `VITEST_TWIN_INSTANCE`, naming both.
- **`doctor`** checks the Node range, reports the Vite actually in use, warns about Babel plugins a
  project needs to add, and reports Expo and expo-router setups as covered.
- **`migrate`** reproduces Jest's effective test set and settings, and sorts the project's Babel
  plugins into required, mapped, not needed and unknown.
- **A copied checkout no longer fails with "more than one copy of React"**: the copy builds its own
  precompiled React Native registry on its first run.
- **An experimental `metroConfig: true` option** reads the project's Metro resolution profile
  (source and asset extensions and their order).
